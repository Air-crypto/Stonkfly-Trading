# Fly circuit debugger

The debugger records the actual full retained network at the controller's 10 ms
integration boundary. It does not replace the native integrator, prune the graph,
or write to a deployed paper account. Inputs can run locally or on Modal;
recorded results remain inspectable without model compute.

![Interactive circuit and input controls](assets/fly-debugger.png)

## Open the included recordings

From the repository root after the normal locked install:

```sh
uv run python -m paperlab.debugger serve --out examples/fly-debugger
```

Open <http://127.0.0.1:8765>. No credentials, graph download, or ongoing model
compute are needed to view the included recordings. Choose `fall_learning`,
observation 3, and compare `fall_frozen` to see the action disagreement.
The examples contain real full-network activity driven by synthetic inputs.
The included `market02-online_original` and `market02-reinforcement_gated`
recordings also show a real retrospective market input and its simulated execution
timeline. Their timelines are derived from the immutable second-study ledger;
the source hash is recorded in `timeline_provenance`. This display enrichment does
not rerun or modify the experiment. Neither example contains account data.
Full-neuron lookup requires the larger NPZ files,
which are generated by the commands below and excluded from Git.

## Run and inspect new inputs

With the lab already deployed and the Modal SDK authenticated, use cloud compute:

```sh
uv run python -m paperlab.debugger serve --backend modal --out runs/cloud-debugger
```

The form now says **Run on Modal (cloud)**. The browser and small inspection
server are local; full-network computation runs in Modal and continues if the
laptop sleeps. On reopening the server, its saved `cloud-job.json` receipt resumes
the same call. Credentials remain in the SDK and are never sent to the browser.
An uncertain submission/result blocks duplicate work rather than resubmitting.
Inspect the recorded Modal call if a receipt says `attention`.

The worker uses Modal single-use containers. A diagnostic batch exposed open-file
reload failures when a native-model container handled a second invocation; a fresh
container per call closes those handles before the next call. This adds startup
latency to queued diagnostic batches; scheduled five-minute calls already normally
start cold. The existing ten-second startup reservation remains unchanged.
The recorder also restores class-method lookup on exit instead of retaining a
bound-method reference cycle around the full brain.

Cloud assays share the existing worker lease and budget ledger. No extra paid
endpoint or always-on GPU is created. A long diagnostic can delay a scheduled
paper cycle; collection runs separately. Assays retain the worker's 600-second
timeout, 2 CPU / 8 GiB universe-mode limits, and conservative reservation. Full
traces persist under `/state/fly-debugger`; the browser downloads compact views
first and larger NPZ files only for full-neuron lookup. Storage and provider
billing must still be checked separately from the compute estimate.

For an explicit deployment, preserve the universe and schedule flags:

```sh
PAPERLAB_SCHEDULE=1 PAPERLAB_FLY=1 PAPERLAB_UNIVERSE=1 uv run modal deploy cloud.py
```

For local computation instead:

Prepare the retained graph once (Python 3.12, C++ compiler, about 1.1 GB of source
downloads, and sufficient memory; plan for 16 GB RAM). Then:

```sh
uv run paperlab fly-prepare --fly-data data/fly
uv run python -m paperlab.debugger study --fly-data data/fly --out runs/study-01 --steps 4
uv run python -m paperlab.debugger serve --fly-data data/fly --out runs/study-01
```

The server binds to loopback and runs one submitted assay at a time. The form
starts an isolated subprocess and displays its progress log. Test rising,
falling, flat, reversal, or shock prices; change plasticity and eta; supply
synthetic news; ablate the header/news strip or the entire image; or inject
bounded current into up to 16 exact retained neuron IDs. All assays start from
pristine native state. A new assay never continues or rolls back the deployed
trader's checkpoint. Closing this local server closes access to this debugger,
but does not affect Modal's scheduled traders.

For one CLI capture:

```sh
uv run python -m paperlab.debugger capture --fly-data data/fly --out runs/custom/capture-01 --preset fall --steps 4 --frozen
uv run python -m paperlab.debugger serve --out runs/custom
```

`capture --config config.json` accepts the complete `Assay` configuration:

```json
{
  "preset": "rise", "steps": 4, "probe_steps": 0, "probe_preset": "rise",
  "learning": true, "eta": 0.001,
  "reinforcement": "none", "reinforcement_only": false,
  "view": "original", "news": "none",
  "neurons": [], "current": 0
}
```

Observation count is bounded to 1–8; each observation is 500 ms of neural time.
Extra stimulation lasts the whole observation. Reinforcement stimulates the
identified reward or aversive cells for the unchanged first 200 ms. These are
engineered interventions, not proof that the network recognizes market outcomes.
The `price_only` ablation removes the header and lower strip; it still retains
the original chart grid, scaling, colors, and the same cropped price region.

The **Require reinforcement for updates** checkbox freezes plastic weights and
efficacy memory whenever the observation has no engineered reinforcement. Neural
propagation and KC/DAN rate traces continue. A reward or aversive pulse enables
the original plasticity rule for that observation. This is an experimental credit
assignment gate, not a replacement decoder or a validated biological claim. The
learning panel reports whether plasticity was enabled for each observation.

## Probe retained learning

Expand **Test retained learning** and set 1–4 frozen probe observations. Training
plus probe observations must total at most eight. Choose the probe's price
sequence independently from training. The probe resets voltage, adaptation,
queues, sensory state, and KC/DAN rate traces to the native initial state, while
retaining plastic weights and efficacy memory. It verifies those invariants
before proceeding. Probes have no learning, reinforcement pulses, extra current,
or news, and record exact weight/memory hashes at the boundary.

For example, this config trains on rising synthetic prices with reward pulses,
then probes falling prices with frozen trained weights:

```json
{
  "preset": "rise", "steps": 4, "learning": true, "reinforcement": "reward",
  "probe_steps": 4, "probe_preset": "fall"
}
```

Pass the file to the existing `capture --config` command or enter these settings
in the Modal form. Every run still starts pristine; this does not edit a deployed
trader. Use **Highlight weight changes from pristine state** to see retained
weight deviations during frozen probes. The default shows changes within the
current observation, which should be zero for a frozen probe. Old recordings
without the additional arrays disable the pristine-relative view.

Observation labels distinguish training and probe phases. Comparisons align by
phase and within-phase index, so a shorter training phase cannot shift probe
pairing. Native binary mismatches are highlighted: same RGB inputs across Mac
and Linux builds have produced different fixed-decoder outputs. Control build,
inputs, and reset semantics before attributing differences to learning. The
full-native test verifies that a frozen stimulated training phase followed by a
reset probe reproduces the fresh control, and that trained efficacy memory and
weights survive the reset without further probe updates.

## What the views mean

- **Neuron activity:** actual bin spike counts. The voltage plot shows voltage
  at each bin boundary; it does not resolve individual 0.1 ms spike waveforms.
- **Connection activity:** a recorded presynaptic neuron spiked. A highlight
  does not prove transmission, a postsynaptic spike, or causal influence.
- **Amber connections:** plastic weight differs from its value at the start of
  the selected observation. The edge inspector shows exact endpoints and weight.
- **Learning:** L2 weight displacement, changed-edge count, KC/DAN rate traces,
  memory states, and clipping. Optimizer loss and backprop gradients are `null`
  because this rule has neither; the UI never invents them.
- **Decoder:** whole-observation mean DNp20 firing rates, DNpe017 gate spikes,
  and the fixed BUY/SELL/HOLD mapping. A positive rate difference still produces
  HOLD if the gate does not spike.
- **Market timeline:** every decision slot, including skipped quotes and terminal
  marks, with simulated fill status and sleeve equity. A neural BUY is not a fill.
  Market comparisons align by decision timestamp rather than compressed recording
  index, so missing observations cannot silently shift the pairing.
- **Graph:** the native computation uses all 166,700 neurons and 25,582,938
  directed connections. The view selects the most active 18 visual and 48 KC
  cells, identified DAN/MBON/output cells, and requested stimulation IDs.
  Connections are actual graph edges between displayed endpoints. Missing
  intermediate neurons can make visual or decoder groups appear disconnected.
  Functional column positions are not anatomical coordinates.

Every observation produces `step-NN.npz` with **all** neuron IDs, counts, voltages,
all 7,835 plastic edges, bin weights, KC/DAN traces, and memory states; an exact
input PNG; and a report with native/source hashes. `view.json` is a bounded
rendering export. The input hashes allow checking identical sensory input across
arms. Use the exact-ID lookup against full recordings to inspect cells outside
the default view. Native checkpoints remain platform/build dependent.

## First controlled study

The [predeclared protocol](../reports/fly-debugger-protocol-01.json) has eight
arms, four observations each, identical pristine initial state per arm, and no
selection by profitability. The [complete results](../reports/fly-debugger-study-01.json)
include every arm, all decoder values, spike hashes, and learning diagnostics.

| Comparison | Different actions / 4 | Observed implication |
| --- | ---: | --- |
| Rising prices: learning vs frozen | 0 | Activity changed; action sequence did not |
| Falling prices: learning vs frozen | 1 | Plasticity affected a downstream action |
| Rising vs falling prices, learning | 2 | Sensory input affects later decisions |
| Reward vs aversive pulses | 0 | Distinct reinforcement changed spikes, not these actions |
| Default vs 10× lower eta | 0 | Lower eta alone did not change these actions |
| Original vs header/news-strip removal | 1 | Non-price display regions can change a decision |

In the falling-price arm, observation 3 was BUY with learning and HOLD frozen.
The learned gate spiked once; the frozen gate did not spike. A rising chart and
a falling chart both began with BUY. These observations identify decoder gating,
input encoding, and credit assignment as subjects for further tests. They do not
show that every falling market should produce SELL or establish an improved
trading strategy. The assays execute **no trades** and measure no financial return.

Four observations cover only two seconds of neural time. This is a deterministic
mechanics study on fixed synthetic inputs, without a statistical performance
claim. The native verification checks that instrumentation preserves the
unrecorded spike/memory result, reset reproduces it, and frozen weights do not
change. Run it explicitly with a prepared graph:

```sh
FLY_TRACE_DATA=data/fly uv run python -m pytest tests/test_fly_trace.py -q
```

Further improvement work must compare frozen and learning policies on the same
chronological market observations, with next-observation fills and fees, slippage,
spread, unavailable inventory, and untouched validation windows. Do not deploy an
assay winner or reverse a live account merely because a visualization looks better.

## Sealed market replay

`fly_market_study` separates training, development selection, and subsequent test
windows on an immutable discovery snapshot. The predeclared arms are pristine
frozen, trained frozen, ongoing plasticity, 10× lower training eta, and header/news
strip ablation. The full retained graph and fixed decoder stay unchanged.

```sh
mkdir -p runs/market
uv run modal volume get fly-paper-lab-universe universe-snapshot.db runs/market/universe.db
uv run python -m paperlab.fly_market_study seal --archive runs/market/universe.db --out runs/market/plan.json
# Local replay of exactly that sealed plan:
uv run python -m paperlab.fly_market_study run --plan runs/market/plan.json --fly-data data/fly --out runs/market/result
```

For cloud execution, submit the sealed envelope through the existing worker and
save the returned call ID before waiting; do not run this snippet again to poll:

```python
import json
from pathlib import Path
import uuid
import modal

root = Path("runs/market")
receipt = root / "cloud-call.json"
if receipt.exists():
    raise RuntimeError("Inspect the existing call; do not duplicate it")
request = {"run_id": "assay-market-" + uuid.uuid4().hex,
           "market_plan": json.loads((root / "plan.json").read_text())}
receipt.write_text(json.dumps({"status": "submitting", "run_id": request["run_id"]}))
call = modal.Function.from_name("fly-paper-lab", "worker", environment_name="main").spawn(debug=request)
receipt.write_text(json.dumps({"status": "running", "call_id": call.object_id, "run_id": request["run_id"]}))
print(call.object_id)
```

Poll that same call with `modal.FunctionCall.from_id(saved_id).get(timeout=0)`;
`TimeoutError` means it is still pending. Results live under its isolated
`/state/fly-debugger/<run_id>` directory. `protocol.json`, `development.json`,
`selection.json`, `results.json`, and `summary.json` preserve the audit trail.
The frozen and ongoing-plasticity test arms also emit full traces and `view.json`
files for the debugger.

Cohort formation uses the earliest historical eligibility and a fixed 15-minute
formation period, never future returns or survival. At most two of four $250
sleeves are used; the other sleeves stay in cash. The default is three decisions
per 15-minute phase. Each phase has fresh paper cash and reset neural dynamics;
post-training weights are restored for development and test. The online arm can
update during each evaluation phase, but development updates do not carry into
test. Frozen evaluation receives no P&L pulses. This separates weight transfer
from live continuous-state trading and is not a replay of the deployed account.

Orders execute only at a subsequent observed receipt, with the existing spread,
fees, slippage, expiry, and missing-inventory stress valuation. News is disabled
for every arm. Terminal fills are marked without inventing another model decision
or a final reinforcement update. Selection is written before any test simulation
and requires beating both cash and pristine frozen on development. All test arms
are reported; none is automatically promoted. Prorated $20/$40 hosting scenarios
are applied once to the total $1,000 comparison portfolio.

This short replay is exploratory. A phase's tiny sample cannot establish an edge
or a monthly return. Once inspected, its test interval must not be used for another
variant selection; further iterations need a later untouched interval.

| --- | ---: | ---: |
| Pristine frozen | $997.44 | $948.53 |
| Trained frozen | $995.68 | $948.53 |
| Ongoing plasticity | $997.03 | $948.53 |

**No variant passed selection.** The lower-eta test result was better than the

Lower eta and display ablation happened to permit one purchase rather than two

predicted the gap or found profitable trades.

The traces exposed a separate training issue. The original and lower-eta arms
had **no fills and no P&L reinforcement** in training, yet their weights changed
under endogenous dopamine activity. They therefore did not optimize a measured
profit signal in this window. Frozen controls showed zero weight movement.
The subsequent ongoing-plasticity trace changed an action from BUY to HOLD,
but the portfolio was already exposed before the unavailable quote.

## Memory-output intervention study

The [preregistered five-arm protocol](../reports/fly-mbon-protocol-01.json) and
[complete native results](../reports/fly-mbon-study-01.json) test whether the two
plastic-memory output groups can influence the fixed decoder. Every arm begins
pristine, receives the same four flat-price images, and has learning and weights
frozen. Signed current is delivered to all four MBON07 cells or both MBON11 cells
throughout each 500 ms observation. These are deliberately strong interventions,
not learned weight changes or proposed trading controls.

| Intervention | Actions across four observations | Different from baseline | Target spikes across all four observations |
| --- | --- | ---: | ---: |
| None | BUY, HOLD, BUY, HOLD | 0 | MBON07: 12; MBON11: 83 |
| MBON07, −20 current | BUY, HOLD, HOLD, HOLD | 1 | MBON07: 1 |
| MBON07, +20 current | HOLD, BUY, BUY, BUY | 3 | MBON07: 729 |
| MBON11, −20 current | HOLD, HOLD, HOLD, BUY | 3 | MBON11: 36 |
| MBON11, +20 current | HOLD, HOLD, BUY, BUY | 2 | MBON11: 217 |

All 20 observations had zero plastic-weight displacement. Matching input hashes
were verified for every arm. MBON07 negative current removed the third
observation's gate spike: baseline BUY became HOLD despite a positive right-minus-
left rate difference in both. MBON07 positive current increased gate activity,
but its first output was HOLD because the left/right rate difference was zero.
Neither rate difference nor gate activity alone determines the action.

This is causal sensitivity within the implemented network: changing the current
changes outputs while images, initial state, and weights are controlled. It is
not a learned association, a calibrated biological intervention, or evidence of
profit. The +20 MBON07 arm fires far more than baseline and also suppresses
MBON11 activity; it should not be interpreted as a small physiological weight
adjustment. The next test should compare reinforcement-trained memory states
using frozen, pulse-free probes to separate retained associations from immediate
stimulation and transient neural dynamics.

To inspect the included recording, use the read-only server at the start of this
guide, select `mbon01-mbon07_inhibit`, and compare `mbon01-baseline`. Observation 3
shows the action disagreement. The comparison table now includes gate counts.
To reproduce an arm, copy its complete configuration from the protocol into a
JSON file and pass it to `capture --config`, or enter the same values in the cloud
form. MBON07 IDs are `12855,15626,18603,515338`; MBON11 IDs are listed in the
protocol. The full recordings remain available in their isolated cloud runs.

![Signed MBON stimulation and gate-dependent decoder comparison](assets/fly-mbon-comparison.png)

## Retained-learning results

The [registered retention protocol](../reports/fly-retention-protocol-01.json)
and [all eight native reports](../reports/fly-retention-study-01.json) separate
retained memory from immediate stimulation. Every arm receives four rising-chart
observations. The neural dynamics, sensory adaptation, and rate traces then reset;
plastic weights and efficacy memory remain. Four rise or fall probes follow with
learning disabled, no reinforcement, no extra current, and no news. The graph and
fixed decoder remain unchanged.

| Training | Probe | Retained weight L2 | Probe actions | Different from frozen / neutral |
| --- | --- | ---: | --- | ---: |
| Frozen | Rise | 0 | BUY, HOLD, HOLD, HOLD | 0 / 1 |
| Frozen | Fall | 0 | BUY, SELL, BUY, HOLD | 0 / 0 |
| Neutral plasticity | Rise | 10.662 | BUY, HOLD, BUY, HOLD | 1 / 0 |
| Neutral plasticity | Fall | 10.662 | BUY, SELL, BUY, HOLD | 0 / 0 |
| Reward | Rise | 13.107 | BUY, HOLD, BUY, BUY | 2 / 1 |
| Reward | Fall | 13.107 | BUY, SELL, SELL, HOLD | 1 / 1 |
| Aversive | Rise | 17.174 | BUY, HOLD, HOLD, HOLD | 0 / 1 |
| Aversive | Fall | 17.174 | BUY, SELL, BUY, HOLD | 0 / 0 |

All 32 probes had zero weight updates. Within each training group, the rise/fall
arms produced identical training spike hashes and identical retained weight and
efficacy-memory hashes. All arms used the same native binary and graph, with
identical images for each probe cue. The frozen rising probe reproduced all four
pristine training spike hashes. Float32 norm reductions differed by about
0.000002 between the two aversive hosts despite identical array hashes; the audit
compares hashes for exact memory identity.

The fourth rising probe illustrates the gate's role: reward training produces
BUY with R−L = 6 Hz and four gate spikes; neutral training produces HOLD with
R−L = 8 Hz and zero gate spikes. A larger rate difference alone is not a stronger
buy decision. Aversive training changes the most weights but leaves all eight
probe actions equal to frozen controls. It still changes neural activity, so
unchanged actions do not mean unchanged internal dynamics.

These are lasting effects in the implemented model, not evidence that reward
learned profitable trading. Neutral training already changes behavior; the probe
sequences are short and deterministic, and their synthetic chart scaling yields
repeated images within each cue. No trades, fees, unseen market predictions, or
statistical generalization are tested. The next [counterbalanced protocol](../reports/fly-retention-protocol-02.json)
uses falling-chart training with the same rise/fall probes and controls to test
whether reinforcement effects depend on the training cue. No paper policy was
promoted from this experiment.

In the included viewer, select `retention01-reward_rise` and compare
`retention01-neutral_rise`. Select **probe 4**, then enable **Highlight weight
changes from pristine state**. Amber connections and the nonzero L2 show retained
weights; disable the checkbox to see that updates within the probe are zero.
The comparison pairs training and probe phases separately. Its configuration
disclosure identifies the changed experimental factor.

## Counterbalanced training cues

The [second registered protocol](../reports/fly-retention-protocol-02.json) repeats
all eight arms with falling-chart training. [Complete results](../reports/fly-retention-study-02.json)
and the [cross-study audit](../reports/fly-retention-counterbalance.json) retain
every outcome. All other configurations and executed source hashes match the
first batch. Both frozen probe cues reproduce exactly across batches; trained
weights and memory reproduce within each batch; all 64 probes across the two
studies have frozen weights. No failed or unfavorable arm was replaced.

| Falling-chart training | Probe | Retained weight L2 | Probe actions | Different from frozen / neutral |
| --- | --- | ---: | --- | ---: |
| Frozen | Rise | 0 | BUY, HOLD, HOLD, HOLD | 0 / 1 |
| Frozen | Fall | 0 | BUY, SELL, BUY, HOLD | 0 / 1 |
| Neutral plasticity | Rise | 15.877 | BUY, HOLD, HOLD, SELL | 1 / 0 |
| Neutral plasticity | Fall | 15.877 | BUY, SELL, SELL, HOLD | 1 / 0 |
| Reward | Rise | 16.001 | BUY, HOLD, HOLD, HOLD | 0 / 1 |
| Reward | Fall | 16.001 | BUY, SELL, BUY, HOLD | 0 / 1 |
| Aversive | Rise | 30.557 | BUY, HOLD, HOLD, HOLD | 0 / 1 |
| Aversive | Fall | 30.557 | BUY, SELL, BUY, HOLD | 0 / 1 |

Changing the training cue changes three of eight neutral probe actions and three
of eight reward probe actions. Aversive probe actions stay equal to frozen controls
under both training cues, although their underlying spike hashes and weights
differ. Reward after rise training adds late BUY outputs on the rising probe;
reward after fall training leaves that probe at the frozen BUY/HOLD pattern.
Relative to neutral training, both reward and aversive stimulation remove the
fourth rising-probe SELL after fall training. This is not evidence that either
reinforcement signal has learned the meaning of a profitable BUY or SELL.

The audit reports reinforcement-minus-neutral rate and gate differences for each
training/probe combination. It then subtracts the rise/fall probe contrast across
training cues. For example, the fourth-probe reward gate interaction is five
spikes: the rising probe's effect is +4 after rise training and −1 after fall
training, while both falling-probe effects are zero. These are deterministic
model responses, not independent samples or a significance test.

Select `retention02-reward_rise` and compare `retention01-reward_rise` in the
included viewer. Training images correctly show **No** in the identical-input
column; probe images show **Yes**. Probe 4 is HOLD after fall training and BUY
after rise training. The evidence supports persistent input-dependent effects,
but does not select a trading policy. The next market replay retains the
reinforcement gate and unchanged baselines on a fresh chronological interval,
with quote coverage and simulated fills reported alongside equity.

## Price magnitude lost in the visual adapter

The [deterministic input audit](../reports/fly-input-scale-audit.json) found a
specific information loss before the neural simulation. With the same product,
100 evenly spaced observations, and news disabled, a 1% rise and a 20% rise
produce exactly the same 320×180 input bytes. A 0.2% fall and a 20% fall also
match exactly. The audit retains six fixtures and four comparisons, including a
non-matching pair: the 0.2% rising image differs from the 20% rising image by 29
pixels because the upstream renderer enforces a minimum chart span.

The renderer scales prices by each window's range. It draws bid/ask text at
y=165, but our adapter then covers y=140–179 with the news strip. Thus the original
numeric quote text cannot recover magnitude in these fixtures. From the same
neural state, identical RGB inputs cannot identify which of the paired histories
occurred. This is a verified sensory limitation; it does not by itself prove
which trades would improve.

![Different return magnitudes produce identical inputs](assets/fly-input-scale-audit.png)

available at the observation time. It separates these fixtures without introducing
a suggested action. Market effectiveness requires a fresh sealed interval; the
completed market test must not be reused to select it. The full graph, fixed
decoder, execution costs, and original recordings remain controls. Existing paper

## Experimental fixed return input

Choose **Fixed return magnitude (experimental)** in the debugger's visual-input
menu. **Price movement multiplier** scales the synthetic preset's changes about
its initial level: 0.05 yields one twentieth of the usual movement. The separate
probe multiplier controls the frozen probe after a training/reset boundary.
Both default to 1, preserving existing presets.

The candidate redraws only the chart region. It leaves the product header and
news strip intact. For each trailing window, it computes `r = log(mid/reference)`,
where the reference is the first of at most 100 observed prices. It maps this to
`y = 85 - 51 * asinh(r / 0.01) / asinh(log(100) / 0.01)` and clips outside the
0.01×–100× reference-price bounds. Amber dots expose clipped observations. The
mapping is fixed across windows, rather than divided by each window's price
range. Its nonlinear scale makes small moves visible while accommodating large
ones; it still has finite pixel resolution and can lose detail at the bounds.

These are declared sensory parameters, not values fitted to trade outcomes.
There is no suggested action, equity, fee threshold, or future price in the
encoding. The original mode remains byte-identical. Tests verify the documented
small/large input collisions separate, header/news pixels remain unchanged,
future and older-than-window prices have no effect, denomination scaling leaves
the tested images unchanged, and clipping is marked. A full-network test verifies
different magnitude inputs produce different spike-count recordings with weights
